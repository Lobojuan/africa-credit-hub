## Part B — Scoring core deep audit (COMPLETE)

### CRITICAL
**F1 — Utilization factor (15% weight) is dead code for every real borrower.**
`credit-score.ts:253-286` reads `a.creditLimit`, but `credit_accounts` has NO creditLimit column (only `telco_credit_scores` has one). Every production call passes raw DB rows → utilization penalty is ALWAYS 0. A borrower with maxed-out facilities loses zero points (up to -120 never applied). Unit tests mask it by passing in-memory objects with creditLimit. Fix: add `credit_limit` column (BoG spec has facility limits) or derive for revolving types; test with real row shape.

### HIGH
**I1 — Every inquiry ever recorded lowers the score — no consent, no soft/hard split, no 12-month window.** All 10 call sites pass `inquiries.length` raw; `consentProvided` defaults false and is never required. The factor text "in the last 12 months" is false — penalties are lifetime. Fix: count only consented, hard, ≤12-month inquiries.
**I2 — Soft-pull endpoint permanently 500s.** `routes.ts:18485` calls `(calculateCreditScore as any)(borrower, accounts, ...)` — arguments shifted by one, hidden by the cast. `borrower.filter` throws. Naive fix would return garbage. Correct call: `calculateCreditScore(accounts, hardInquiries.length, judgments, borrower.isPep ?? false, altData)` + exclude isSoftPull everywhere.
**C1 — Same borrower, different scores depending on the door.** Internal/consumer/PDF paths include altData; external bank API and dashboard omit it (up to ~90 pts lower via API); decision-rules engine omits altData AND passes inquiryCount=0 (decisions run up to 100 pts higher than the disclosed score). For a licensed bureau this is a regulatory finding. Fix: one `assembleScoreInputs(borrowerId)` used by every surface.
**F2 — Empty alt-data rows grant a free +64 thin-file boost.** Zero-transaction rows get an assumed 80% on-time ratio. Any lender can post `{source:"mobile_money"}` with no data → 600→664. Fix: require minimum transaction count; default ratio 0.
**B1 — Cross-lender tradeline tampering via batch upload.** Upsert key includes caller-supplied free-text `lenderInstitution` with no ownership check — Lender A can overwrite Lender B's delinquency (or fabricate one). Fix: derive lenderInstitution from uploader's org.
**B2 — Global borrower match + silent identity overwrite in batch.** nationalId matched across all countries/orgs, then name/phone/DOB unconditionally overwritten from the batch row. Typo'd ID = someone else's delinquencies + rewritten identity. Fix: scope matching, never auto-overwrite identity, route conflicts to review.
**A1 — monthSpan systematically overstates income.** N salaries span N-1 months (3 credits in 90 days → income ×1.5); income and expenses use different denominators → inflated disposable income → `maxRecommendedNewCredit` over-lends. Fix: normalize both by periodDays/30.
**A2 — Loan disbursements & savings withdrawals counted as income.** Borrowers cycling digital loans show rising "income" when most distressed. Fix: exclude these types from income candidates.
**A3 — Uploaded PDF overwrites borrower.monthlyIncome as trusted.** LLM-parsed statement (≥5 txns) writes back permanently, feeds decision DTI. Fabricated PDF → inflated income on record. Fix: remove bank_statement_pdf from write-back or gate behind maker-checker.
